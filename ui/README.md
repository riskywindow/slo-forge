# SLOForge artifact explorer

This is a static, framework-free TypeScript UI for both the logical SLOForge
`report-data.json` contract and the multi-file SLOForge Fabric demo manifest.
It has no backend, authentication, database, or external runtime dependency.

```bash
cd ui
npm ci
npm run dev
```

Use **Load artifact** to choose a local report. A served artifact can instead be
selected with `?data=/path/report-data.json`, or by setting
`VITE_REPORT_URL` when building. For example, after `npm run build`, serve the
repository root and open:

```text
http://127.0.0.1:4175/ui/dist/?data=/reports/demo/report-data.json
```

To inspect the physical topology, rank/expert placement, communication profile,
Autopsy diagnosis, counterfactuals, and recovery audit produced by
`make fabric-demo`, serve the repository root and open:

```text
http://127.0.0.1:4175/ui/dist/?data=/artifacts/fabric-demo/manifest.json
```

The Fabric loader resolves only the required artifacts named by the manifest
and verifies every response against its recorded SHA-256 before rendering.
For a local file picker, use a pre-composed
`sloforge.fabric.ui-bundle/v1` JSON object because browsers cannot grant a
single selected manifest access to sibling files.

Validation commands:

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

The logical generated-demo conformance test runs when
`reports/demo/report-data.json` exists. Fabric parser, transform, and component
tests consume the checked-in artifacts generated by the deterministic Fabric
demo, so displayed benchmark and recovery values are never duplicated in UI
source code.
