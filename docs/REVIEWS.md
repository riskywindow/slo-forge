# Adversarial architecture and performance-methodology review

Review date: 2026-08-01 (artifact timestamps are 2026-08-02 UTC)
Scope: integrated repository, `artifacts/demo`, `reports/demo`, compiler/model/optimizer/controller/fault/exporter paths
Standard: claims must follow executed work and raw evidence, not schema names or intended design

## Verdict

SLOForge has a substantive compiler core: strict cross-language IR, explicit feasibility/profile/model/selection passes, deterministic Rust simulation, a bounded streaming gateway, rejected-candidate diagnostics and hash-bound report inputs. It is materially more than a YAML generator.

The checked-in CPU demo is a useful systems integration run, but it does not establish H1 or H2, and its H3/H4 numbers are analytical self-consistency results. More seriously, several artifact fields currently claim stronger provenance than the implementation provides. The plan's nominal 95% intervals achieved only 54.17% prefill coverage, “measured” optimizer trials are analytical transformations, and H4 latency is computed from scenario duration. Those semantics must be fixed before presenting the EvidenceBundle as production-quality measurement evidence.

Modal and Truss support is current-API-shaped offline packaging, not engine-faithful deployment lowering. The validators are valuable, but a plan selecting vLLM, SGLang, TensorRT-LLM or the mock engine is still emitted as a Transformers wrapper. That is a silent runtime switch and violates the repository's own execution rule.

## Compiler-versus-generator assessment

The compiler claim is justified by the repository's strict versioned IR, explicit migration/validation boundaries, feasibility diagnostics, profile/model/optimizer passes, non-dominated frontier and evidence binding. Those semantics exist before export and are independently useful.

The backend claim needs narrower wording. Local/Docker/Kubernetes/Modal/Truss output is currently a family of partial packaging emitters. There is no target capability negotiation or proof that runtime, precision, batching, topology and policy survive lowering. Calling the whole project a compiler remains accurate; calling every emitter a production backend or semantics-preserving compiler target does not.

## Modal and Truss depth

The review accepts these strengths: generation is offline; no credentials or remote calls are required; dependencies are pinned; syntax/schema checks are bounded; generated manifests hash outputs and record `deployed: false`; documentation does not imply official Baseten support.

The minimum safe next state is rejection of non-Transformers plans and removal of the mock model export from claims of runnable cloud output. Production depth additionally requires engine-native entrypoints, dtype/quantization/parallelism mapping, cache/batching/compilation mapping, OpenAI streaming contract tests, model-license/download validation and one budget-authorized provider smoke run. Modal memory snapshots need a phase-safe load path; a generic `device_map="auto"` call inside ordinary snapshot capture is not enough for GPU correctness.
